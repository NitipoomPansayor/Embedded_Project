# AI Assistant Guide

Shared instructions for AI coding assistants (Claude, Gemini, …) working in this repo. `CLAUDE.md` and `GEMINI.md` just import this file. **Edit this file, not those.**

## Project

People Counting Gate: an IoT occupancy counter for room doors (Embedded System Lab final project, Fall 2026).
STM32 NUCLEO-F411RE reads a laser beam (KY-008 + KY-018) and an ultrasonic sensor, works out direction, and owns the count. It talks over UART to an ESP32-S3, which syncs with Firebase Realtime Database. A React website shows each room as Empty / Available / Full.

Read these before making design decisions:
- [docs/requirement.md](docs/requirement.md): what the system must do
- [docs/system_architecture.md](docs/system_architecture.md): how it works, pin map, UART protocol, Firebase data model

## Working rules

1. **Ask, don't assume.** If a requirement, pin, part or behavior is unclear or not in the docs, ask the user before writing code. Don't invent hardware the team doesn't have.
2. **Don't commit or push** unless the user asks.
3. **Never commit secrets.** WiFi passwords, Firebase keys and device passwords go in `mcu/include/secrets.h` and `web/.env` (both gitignored). Keep `secrets.example.h` / `.env.example` up to date.
4. **Keep the docs true.** If you change behavior, pins, the UART protocol or the Firebase data model, update `docs/system_architecture.md` (and `docs/requirement.md` if a requirement changes) in the same change.
5. **The UART protocol is a contract.** Change the STM32 side, the ESP32 side and the protocol table together.
6. Write code, comments and docs in English.

## STM32 rules (`stm32/`)

- Files generated by CubeMX: only edit inside `/* USER CODE BEGIN ... */` / `/* USER CODE END ... */` blocks. Anything outside is erased when the code is regenerated.
- Pin and peripheral changes are made in `Embedded_Project.ioc` (CubeMX), not by hand-editing init code. Tell the user which CubeMX settings to change if you can't run CubeMX.
- Put our logic in our own modules (`app_main.c`, `beam.c`, `ultrasonic.c`, `counter.c`, `link.c` in `Core/Src`, headers in `Core/Inc`). `main.c` only calls `app_init()` / `app_loop()` from USER CODE blocks.
- Keep `counter.c` and the protocol parsing in `link.c` free of HAL calls so they can be tested on a PC.
- No `HAL_Delay` in the main loop: use `HAL_GetTick()` timing. Keep interrupt handlers short. No `malloc`.
- USART2 = debug log (ST-LINK USB). USART1 = ESP32 link.
- Build/flash: in STM32CubeIDE (Project → Build, Run → Debug).

## ESP32 rules (`mcu/`)

- PlatformIO project. Pin library versions in `platformio.ini`.
- Commands: `pio run` (build), `pio run -t upload` (flash), `pio device monitor` (serial log).
- Non-blocking loop: WiFi/Firebase reconnects must not stop UART handling.

## Web rules (`web/`)

- React + Vite. Firebase config only from `import.meta.env.VITE_FIREBASE_*`.
- Commands: `npm install`, `npm run dev`, `npm run build`, `firebase deploy`.
- Room status (Empty / Available / Full / Offline) is computed in the UI from `count`, `capacity`, `lastSeen`; it is not stored.
- The website never writes `count` directly; admin corrections go through `rooms/<id>/command`.
- Must work on a phone screen.
